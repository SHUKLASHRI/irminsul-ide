How It Works

Under the hood of the AST static analysis and refactoring engine.

1

AST Ingestion & Parsing

Irminsul IDE walks your codebase without executing code. Python's standard library ast parser extracts function signatures, class hierarchies, import statements, and call sites safely.

tree = ast.parse(source)
→ 24 modules indexed
→ 142 symbols resolved
2

Layer & Complexity Topology

The engine infers architectural roles (Presentation, Services, Persistence, Core) and computes cyclomatic complexity scores. Nodes are positioned automatically via Sugiyama or Force-Directed graph algorithms.

Layers: [API, Service, DB]
Complexity: Low (1) to High (12)
Layout: Hierarchical Sugiyama
3

Tarjan SCC Cycle Detection

Circular imports are isolated in linear O(V + E) time using Tarjan's Strongly Connected Components algorithm. Cyclic paths are immediately isolated into a dedicated HUD and highlighted in amber.

SCC detected: [auth, db, auth]
Severity: High Cycle
Recommendation: Extract interface
4

Atomic Multi-File Refactoring

Renaming a symbol updates every import, call site, and definition across the repository. A dry-run diff verifies syntax integrity before applying atomic writes to disk.

Files modified: 4

Frequently Asked Questions

Everything you need to know about security, architecture, and compatibility.

Does Irminsul IDE execute my Python code during analysis?
No. Irminsul IDE exclusively uses Python's standard library ast (Abstract Syntax Tree) parser. It parses syntax tokens into grammar trees without executing code or importing modules at runtime. This completely protects your environment from side-effects, unwanted network calls, or malicious untrusted scripts.
How does Tarjan's SCC cycle isolation work?
The engine models repository imports as a directed graph. It runs Tarjan's algorithm to partition the graph into Strongly Connected Components in linear \(O(V + E)\) time. Any component with 2 or more interdependent nodes forms a cycle and is immediately flagged in amber with depth metrics and actionable dependency-inversion guidance.
Is my code sent to any cloud server or telemetry endpoint?
Absolutely not. Irminsul IDE runs 100% locally on your machine. There are no external analytics, no tracking beacons, no external API calls, and zero telemetry. It is completely safe for air-gapped corporate environments and proprietary intellectual property.
Can I use Irminsul IDE alongside VS Code or PyCharm?
Yes! Irminsul IDE operates directly on your source folder. You can keep your primary editor open side-by-side. When you save changes in your editor, pressing F5 in Irminsul re-analyzes the project in milliseconds. Alternatively, you can edit directly inside Irminsul using the built-in Monaco code editor.
How does Safe AST Rename prevent breaking changes?
Unlike text search-and-replace, the refactor engine computes precise AST character offsets for the target symbol, imported aliases (from x import y as z), and call sites across all files. It generates a multi-file diff and validates that the modified source produces a valid AST tree before executing atomic disk writes.
What operating systems and Python versions are supported?
Irminsul IDE supports Windows 10/11 (64-bit .exe & zip), macOS 12+ (Universal DMG for Apple Silicon M1/M2/M3/M4 & Intel), and Linux (x86_64 AppImage & tarball). The static AST engine can analyze projects written in Python 3.7 through Python 3.13+.

Open Source Security & First-Time Launch Notes
  • Windows SmartScreen: Irminsul IDE binaries are 100% open-source and free of UPX packers. On first launch of a newly released version, Windows SmartScreen may show "Windows protected your PC". Simply click "More info" → "Run anyway" to launch.
  • macOS Gatekeeper: If macOS prompts that the developer cannot be verified, right-click IrminsulIDE.app in Applications and choose "Open" (or run xattr -cr /Applications/IrminsulIDE.app in Terminal).
  • Linux: Remember to grant execution permissions by running chmod +x IrminsulIDE-v1.0.0-x86_64.AppImage in your terminal before launching.
